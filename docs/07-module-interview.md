# 07 · 模块：面试

> 状态：**当前设计权威** · 取代 owner-career-journey §8、proactive-career-director §13、career-operations-loop §16 与 §23–25 等
> 用户入口：岗位工作区的「面试」标签页（PROPOSAL：不再作为一级入口） · 主要代码：`backend/app/services/career_interviews.py`、`ai_interviews.py`、`interview_scoring.py`、`career_learning.py`；`frontend/src/app/interview/`

## 1. 目的

每一轮面试都基于**这个岗位的研究、这个人的证据、上一轮的学习**来准备，而不是生成一份通用题库。面试结束后，复盘结果回流，让下一次准备更准。

## 2. 主动链路

```text
面试邀请（来自邮件 / 日历 / 手动添加）
  → Career Director 做一次有边界的判断：读取职业快照、岗位研究、已审核的面试学习
  → 准备计划出现在「今天」和岗位工作区
面试前：分轮准备 + 练习
面试结束（日程时间已过）
  → 每日回顾生成一个复盘任务，问题由模型挑选
  → 用户的回答成为有来源的学习候选 → 在档案的「待确认」中审核
```

准备和复盘都**不会**写入已确认的 Career Truth，也不会联系任何人。

## 3. 分轮准备

准备时读取：岗位共性和差异、本人证据缺口、当前面试轮次、团队研究、前几轮和其他已审核的面试学习、近期有来源的面经、**实际提交的简历版本**。

界面上必须说明这些信息具体改变了哪些练习，例如「因为上次『系统设计扩展性』那题答得弱，今天增加 2 道相关追问练习」。

反问清单按轮次和当前未知项**动态生成**，下表只是用途示例，不是写死的流程：

| 轮次 | 反问方向示例 |
| --- | --- |
| HR / 招聘沟通 | 后续流程、时间、下一轮形式、部门归属、职级 |
| 一面 / 技术或业务面 | 实际任务、现有问题、约束、协作方式、成功标准 |
| 二面 / 负责人 | ownership、跨团队关系、优先级、资源和决策权 |
| 后续轮 / offer 阶段 | 汇报关系、工作节奏、评价机制、成长空间 |

得到的回答作为有来源的候选，写回同一个岗位的研究。不推测面试官的个人隐私或性格。

## 4. 练习

- AI 模拟面试（`/interview/ai`）：基于上述准备内容出题和追问。
- 姿态与表情反馈（`/interview/pose`，MediaPipe）：属于**实验性 PoC**。PROPOSAL：默认隐藏，在设置中开启。
- 没有真实记录时，可以做明确标注为「演练」的练习；但真实面试的复盘验收保持 `NOT_RUN`。

## 5. 逐题复盘

- 优先读取真实的转写记录；没有记录时，用 Ask 请用户回忆，并明确标注「回忆」、遗漏和不确定性。
- 每道题保存：原问题、实际回答、追问或对方反应、考察的能力、做得好的地方、薄弱之处、依据、改进后的答案、练习建议。
- **建议答案与实际回答分开保存**，不能倒写成用户当时已经这么答了。
- 复盘同时更新：待核实的团队或流程信息、后续安排、题目频次、故事素材库、弱项。
- 撤回、不可信或过时的说法，不再被引用。

## 6. 学习回流

```text
复盘 → LearningObservation / 候选 → 用户审核 → 精选职业记忆 / 档案
                                           ↓
                              下一轮准备引用（附引用链）
```

## 7. 状态与可靠性

- 面试进行中重启应用：保留当前轮次；正在运行的评估标记为「失败，可重试」，而不是假装完成。
- 一个面试只对应一个持久记录，「今天」、时间线、岗位工作区都是投影。
