## 3. 每个 PR 做什么、怎么验收

验收以「主线在干净的数据目录下真能跑通」为准。每个 PR 的正文写清：做了什么、删了什么、怎么验收、截图。

### #134 重构 1/4：共用工具层

- **做了**：`core/store.py`、`core/tools.py`（9 个工具）；HTTP / MCP / 命令行三个入口；今天页、岗位页、岗位详情页；`offeru connect` 注册 MCP。
- **删了**：旧 jobs / applications / pools / scraper / email / calendar 路由和页面、引导弹窗、旧测试。
- **验收**：
  1. 今天页勾掉一条待办，最近改动出现「你：完成 xx」，点撤销恢复。
  2. 岗位页添加一个岗位并改状态，今天页的下一步跟着变。
  3. 在 Codex 里（`offeru connect` 之后）说「帮我加一个明天截止的待办」，今天页出现这条，最近改动显示 codex，能撤销。

### PR2 重构 2/4：档案和简历

- **做**：profile / memory / doc(resume) 全部走 save；新工具 read_file、export_resume_pdf；档案页、简历页重写；今天页加两条规则。
- **删**：旧 resume / profile / memory / optimize 路由和服务、ResumeHub 旧组件、旧富文本编辑器。
- **验收**：
  1. 空数据目录，今天页提示「先建档案」→ 填好后提示「写一份简历」。
  2. 导入一份 PDF 简历，档案里出现教育、实习、项目各至少一条。
  3. 写一份 Markdown 简历，导出 PDF：中文正常，排版不溢出。
  4. 在 Codex 里说「按 2 号岗位定制简历」，岗位详情里出现新简历，撤销后消失。

### PR3 重构 3/4：网申、面试、Ctrl+K

- **做**：设置里配置模型；内置 Agent（`/api/agent`，最多 6 步）；Ctrl+K；官网投递助手（apply_chat doc）；面试准备和复盘（review doc）。
- **删**：旧 interview / main_agent / profile_agent / research 路由，旧面试页组件。
- **验收**：
  1. 没填模型时按 Ctrl+K，提示去设置或用 Codex，不报错。
  2. 填好模型，Ctrl+K 输入「腾讯 PCG 后端，下周一截止」，岗位和截止日期都建好。
  3. 在岗位里打开网申，贴 3 道真实题目，每题有回答，回答里的经历都能在档案里找到；关掉再开，对话还在；新事实点「存进档案」后出现在档案里。
  4. 写一段面试复盘，岗位详情出现复盘文档，今天页出现「下次要补的」待办。

### PR4 四期：浏览器插件（提前）

- **做**：插件改接 `/api/tools`；已适配的网申系统自动读页面，其他网站点图标再读；右侧小侧栏，沿用同一份网申对话；输入框旁「填写 / 替换」，悬停预览，可撤销。
- **注意**：这时旧代码还没删，插件只调 `/api/tools`，不碰旧接口。
- **验收**：在一个北森和一个 Moka 的真实网申页上，基本信息和开放题都能填进去，撤销后恢复原内容；提交按钮始终由用户点。

### PR5 重构 4/4：后台 Codex 和清理

- **做**：handoff / handoff_status；新 Skill（≤4KB）；README、QUICKSTART 改成新架构。
- **删**：`app/ops.py`、`app/services/`、`app/agents/`、`app/agent/`、剩余旧路由、旧 Skill 生成器、旧表和旧测试。
- **验收**：
  1. Ctrl+K 说一件长任务，几分钟后最近改动出现 codex 的改动，能撤销。
  2. 如果 `codex exec` 不能无人值守，界面给出可复制的一句话，用户贴到 Codex 里能完成同样的事。
  3. 一台没有装过 OfferU 的电脑，按 QUICKSTART 从零装好，走完 #134–PR4 的验收步骤。

### PR6 桌面小球

- **做**：pywebview 小窗，随 `offeru start` 打开；轮询 overview；有新事情动一下；悬停展开今天的待办，可以勾掉。
- **验收**：Codex 加一条今天的待办，小球在 10 秒内动一下；悬停勾掉后今天页同步。

## 4. 每个 PR 都要过的检查

- 后端 `pytest tests`、前端 `tsc --noEmit`、`vitest run`、`vite build` 都通过。
- 改了界面就截图，放在 PR 正文里。
- 删掉的代码不留兼容层，不留「以后可能用到」的开关。
- 同一个 PR 里更新本页的状态和 DESIGN 里对应的章节。
- 不合并 PR，由产品负责人验收后合并。
