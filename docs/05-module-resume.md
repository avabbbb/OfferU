# 05 · 模块：简历

> 状态：**当前设计权威** · 取代 resume-canvas-design、architecture/resume-design、owner-career-journey §6 等
> 用户入口：一级导航「简历」（PROPOSAL：合并原「简历 / 简历定制 / 工作室」三个入口） · 主要代码：`backend/app/services/resume_*`、`career_resume.py`、`pdf_exporter.py`；`frontend/src/app/resume/`、`app/optimize/`、`app/studio/`

## 1. 目的

简历是一份**可以直接编辑的文档**，不是 Proposal 管理后台。AI 负责准备有证据支撑的改动，用户直接在成品上编辑、查看行内 diff、撤销或恢复，并且在 AI 生成之后仍然拥有完全的手动控制权。

> AI 不是用户唯一的鼠标。最后那 10% 必须能由用户自己完成。

## 2. 页面结构（三栏）

```text
┌──────────────┬──────────────────────────────┬──────────────┐
│ 大纲          │         简历画布               │ 检查器（可收起）│
│ 段落顺序       │    可直接编辑的成品文档          │ AI / 证据     │
│ 显示与隐藏     │    实时分页、A4 / Letter        │ 设计 / 历史    │
│ 改动标记       │                              │              │
└──────────────┴──────────────────────────────┴──────────────┘
```

- **大纲**：点击定位、拖拽排序、显示或隐藏段落、标记（AI 改过 / 手动改过 / 证据警告 / 对目标岗位重要）。它不是第二个编辑器。
- **画布**：日常编辑的唯一界面。支持点击编辑、键盘操作、增删、列表编辑、段落重排、分页可见、缩放、与打印一致的渲染。
- **检查器**：显示当前选中段落的上下文，默认收起。
- 窄屏（`lg` 以下）改为单列，可以纵向阅读、保存和导出。

## 3. 从岗位到定制简历

```text
Career Truth + 目标岗位 + Role Intelligence + 当前简历 + Skill 方法
  → Ask：只问还没决定的事（定位、结构、经历取舍）
  → 准备好的可编辑草稿（L1，自动）
  → 画布上以行内 diff 呈现
  → 用户直接修改，或用自然语言要求修订
  → 一次最终采用（REVIEW）
  → 版本 → PDF / 申请材料
```

- 先读完整的档案、原简历风格和目标岗位，再动笔。
- 每个重要改写都带有：Before、After、为什么改、对应的岗位要求、本人证据、事实门状态。
- **不得新增没有来源的数字、技术、公司、职责范围或成果。**
- 外部 Agent 写的草稿需要返修时，交回原来的 Agent，不在后台悄悄换一个模型替用户重写。

## 4. AI 改动的呈现

| 类型 | 呈现 |
| --- | --- |
| 新增 | 浅色高亮 + 「新增」标记 |
| 删除 | 删除线，可一键恢复 |
| 修改 | 行内 diff；悬停或选中时，检查器显示理由和证据 |
| 证据不足 | 警告标记 +「补充证据 / 加入档案候选」 |

- 按钮只有「采用」/「修改」/「跳过」（见 [02 §4.1](./02-interaction-design.md#41-审批对用户怎么呈现)），可以作用于一段，也可以作用于已展示的整份改动。
- 批量采用必须原子执行，同时保留逐项的证据、事实门、过期检查和审计。
- 「修改」就是自然语言续写：保留任务身份，只重新生成受影响的段落。

## 5. 人工编辑与 AI 改动共存

- 用户手动编辑后，覆盖同一块内容的旧 Proposal 自动过期（stale）。
- 改动不重叠：AI 改动和人工编辑并存。
- 改动在同一块：提示冲突，让用户选择保留哪一方，或合并。
- 区分 AI 改动和用户改动的标记，用户改动永远不被 AI 静默覆盖。

## 6. 安全靠可逆性，而不是事前审批

- **自动检查点**：在大规模 AI 定制、结构重写、换设计之前和之后自动创建。
- **命名版本（不可变）**：在为某个岗位导出、附加到投递、手动「保存版本」、采用最终材料时创建。
- 历史记录用人能读懂的语言，不用修订 ID 作为主要表述：

```text
今天 16:42  腾讯 Agent Runtime 定制版  · 12 处 AI 改动 + 3 处手动编辑  [对比] [恢复]
今天 15:18  产品经理基础版                                            [对比] [恢复]
9 月 29 日  导入的原始简历
```

- 文字编辑、重排、显示或隐藏、设计改动、AI 批量采用，都可以撤销。对可逆的本地编辑，优先提供撤销，而不是事前审批。

## 7. 与 Career Truth 的关系

- 简历文本是申请产物，**不会**自动成为 Career Truth。可以用不同的措辞表达已经验证的证据，不需要改档案。
- 手动加入的、档案里没有依据的新事实：保持可编辑，标记为「未验证」，提供「补充证据 / 加入档案候选」，**不会**静默升级为事实。

## 8. 设计与导出

- 设计系统：Editorial / Classic / Modern 三套预设。原则是克制、打印效果与屏幕一致、清晰的字体层级、关注信息密度。模板与 HTML 简历（原 Studio）作为检查器里的「设计」面板。
- PDF 优先用 managed Chromium（Python Playwright），与预览共用同一个 React 渲染器；失败时回退到 ReportLab；仍然失败就显示可重试的错误。导出的 PDF 必须对应用户实际采用的版本。

### 8.1 「纸」模板：成品即编辑器（2026-10 已实现，切片 ①）

- 新模板 `paper`（「纸 · 可直接编辑」），组件 `frontend/src/app/resume/components/templates/ResumePaper.tsx`。同一个组件既是导出 PDF 的成品，也是工作区画布：`editable=true` 时页面上每段文字都能直接点击修改，所以画布所见就是导出所得。
- 编辑直接写回原始字段（`content_json` 里的 `company / position / startDate / description …`），左侧表单、AI 建议和导出读的是同一份数据；自动保存、撤销、版本沿用现有机制，不调用模型。
- 键盘：回车提交并新增下一条要点，空要点按退格删除，Esc 撤回本次输入；悬停一条经历可删除，段落末尾「+ 添加一条」。
- 分页可见：画布量出成品高度，超过一页时在第一页底部画出分页线并标注超出多少毫米，由用户决定删哪条，而不是自动缩字号。
- 排版约束参考 tw93/Kami（MIT）的 design.md：单一墨蓝强调色 `#1B365D`、暖灰文字层级、衬线两字重 400/500、行高 1.45、页边距 11/13mm、无装饰线与阴影；暖纸 `#f5f4ed` / 白纸可一键切换。中文字体只用 OFL 许可的思源宋体 / Noto Serif SC，**不使用**仅限个人免费的仓耳今楷。
- 其他模板暂时仍是只读预览，画布顶部提供「换成『纸』模板，直接在页面上改」。
- 限制：要点按纯文本编辑，带加粗等富文本格式的那一条在被修改后会变成纯文本；未修改的条目原样保留。
- 测试：`ResumePaper.test.tsx`（直接编辑写回原字段、Esc 还原、未改不提交、增删条目、隐藏要点索引对齐、默认排版只作用于纸模板）。
- 下一切片：③ 排版控件与「压到一页」；④ DOCX 导出。

### 8.2 画布上的 AI 协作（2026-10 已实现，切片 ②）

- **行内 diff**：AI 建议显示在它要改的那一段标题下方，按字比较，新增的字用墨蓝底色，删除的字划掉；每块都可以「采用 / 修改 / 跳过」。画布顶部显示「AI 建议 n 条 · 全部采用 · 只看当前 / 显示对比」。代码在 `components/canvas/CanvasAssist.tsx`、`components/canvas/proposalDiff.ts`。
- **修改后采用**：只改了一句的建议，可以先在原位置改成自己想要的样子再采用（沿用 `edited_text`，后端会对新文本重新做事实门检查）；改了多处的建议，先采用，再直接在页面上改。
- **人工修改优先，冲突按段落判断**（后端 `_change_conflicts_with_manual_edit`）：
  - 用户改了别处，比如简介、样式或其他段落，这条建议照样可以采用，整份提案**不再**因此作废；
  - 只有建议要改的那一段在建议生成后被用户改过，这一条才不能采用：页面标注「以你的版本为准」，提供「跳过」和「让 AI 按我的版本重写」；「全部采用」只采用没有冲突的条目；
  - 拒绝一条建议不会顺带让其他条目的冲突失效；JD 或档案事实变了，仍然让整份提案作废（这条规则不变）。
- **选区浮条与修改意见**：在画布上选中文字，浮条提供「更精炼 / 对齐岗位 / 换个说法 / 留言给 AI」。意见先堆在右下角的托盘里，可以逐条删除，最后点「一次交给 AI」。
- **交给 Agent 的通道**：`lib/agentCompose.ts` 提供邮箱加事件。Agent 面板挂载时取走邮箱里的消息，已挂载的面板也能立即收到；消息一律先进待发送队列，按 D-1 规则发送。提示词要求 Agent 先读取最新工作区、只改圈出的文字、没有证据的数字先问用户，并以可审核的建议提交，不直接覆盖。
- 测试：`CanvasAssist.test.tsx`、`[id]/page.paper.test.tsx`、`AgentPanel.test.tsx`「Agent compose mailbox」、`backend/tests/test_resume_workspace.py` 的两条段落级冲突用例。

## 9. 验收

- 一次单岗位定制：最终采用决定 ≤ 1 次；需要审阅的独立 Proposal 达到 50–80 个即判为不合格。
- 状态可见：已生成 / 未生成 / 失败 / 待审阅 / 已采用。
- 动效不能替代文字状态；支持 reduced-motion 和键盘操作。
- 自动保存、刷新、503 错误下，内容不丢失，错误可见，可以手动重试。
