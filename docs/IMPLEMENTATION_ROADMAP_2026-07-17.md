# OfferU 本地单人版实施路线与验收门槛

> 日期：2026-07-17  
> 输入：`BACKEND_CAPABILITY_AUDIT_2026-07-16.md`、`CONTEXT.md`、`docs/adr/0001` 至 `0028`  
> 目标：把现有局部能力收敛为四个可独立使用、可审计的垂直闭环
> 状态：历史路线快照；其中 Agent runtime 与前端技术栈已被 ADR-0034 至 ADR-0047 及当前实现更新  
>
> 当前 Agent 架构与剩余缺口见 [`docs/architecture/agent-system.md`](./architecture/agent-system.md)。实现时以 `CONTEXT.md` 和最新 accepted ADR 为准。

## 总体发布规则

每个阶段必须同时通过三层门槛：

1. **安全不变量**：要求 100% 通过，任何失败都阻止发布。
2. **概率能力基准**：在固定、版本化、去标识化的标注样本集上达到阈值；模型、提示词、解析器或检测器升级后必须重跑。
3. **端到端与故障恢复**：真实用户路径必须覆盖正常流程、重启、重试、取消、重复输入和上游不可用。

所有阈值都是第一阶段发布下限，不是最终质量目标。基准集、计算方式和失败样本必须版本化，不能只报告平均分或删除困难样本。

## 阶段 0：共同底座

### 用户结果

OfferU 主 Agent 可以可靠委托本地深度执行器；所有模块通过同一来源、观察、确认、审计和记忆收件箱影响使用者职业模型；敏感数据在本地和云端调用边界内均受控。

### 实施范围

- 以 Python/FastAPI 作为唯一业务后端，不再保留或新增第二套 Rust 业务写路径；
- 修复 Codex CLI 已移除参数，Codex 使用结构化输出约束，Claude 使用 JSON schema；
- 深度执行器只承担公司/岗位调研、批量 JD 评估和工作源变化摘要；
- 把现有 `python -m app.cli` 收敛为稳定的 `offeru` 机器 CLI，保留 JSON stdout、schema 发现、稳定退出码、dry-run 和确认契约；
- 新增 `offeru tui` 操作员界面，浏览投递、Agent Run、研究档案、记忆收件箱、提案与审计，并通过 Operation Registry 发起操作；
- 让主 Agent 对话框与 TUI 支持 `/offeru` 技能菜单，以及由 Skill Registry 自动生成的 `/skill-id` 和 alias 直达命令；两种入口解析到同一 Skill ID，只激活 Skill 协议与 allowlist，不执行 shell；
- 将硬编码技能逐步收敛为可版本化、可校验的 Skill 包，声明协议、允许操作、输入输出、所需数据授权和 UI 元数据；第一阶段不允许 Skill 执行任意代码；
- 建立 Source、LearningObservation、MemoryProposal、EvidenceLink 与统一事实门；
- 建立记忆收件箱、来源级联失效和登记工作源的只读增量同步；
- 邮箱与模型凭据进入操作系统钥匙串；
- 数据库、附件、索引、缓存与备份进入统一静态加密边界；
- 云端模型按供应商和数据类别授权；
- FastAPI 默认只绑定回环地址，MCP 保持关闭或具备本机调用方认证。

### 发布门槛

**安全不变量**

- 100% 职业证据写入需要来源和使用者确认；
- 100% Profile 变更建议可以追溯到学习观察与原始来源；
- 来源撤销后，100% 派生对象退出检索、提示词、评分与巩固；
- 密钥、token、邮箱密码和明文敏感附件在数据库、日志、索引、缓存与备份扫描中为 0；
- 未授权的数据类别发往云端模型的调用次数为 0；
- 本地深度执行器直接写职业事实、投递阶段或面试评分的路径为 0。
- GUI、机器 CLI、TUI、斜杠命令对同一写操作产生不同权限、确认或审计结果的数量为 0；
- 斜杠 Skill 命令直接执行 shell 或未注册 Operation 的次数为 0。

**概率与可靠性基准**

- Codex 与 Claude 各执行 100 个固定任务，结构化结果解析成功率不低于 99%，失败必须显式呈现且不得生成伪结果；
- Operation Registry 中已发布操作的 CLI schema、TUI 表单和 Agent tool schema 一致率为 100%；
- 每个已启用 Skill 的斜杠主命令、alias、版本、allowlist 与数据授权声明完整率为 100%；
- 同一学习观察重复输入 10 次只形成一个有效对象；
- 空闲巩固任务在任意步骤中断后重启，不丢失原始观察且不重复晋升。

**端到端与故障恢复**

- 对话或业务模块产生观察 → 空闲巩固 → 记忆收件箱 → 接受/拒绝/撤销 → 后续 Agent 使用结果；
- 登记工作源 → 增量摘要 → 待确认职业证据 → 撤销来源 → 级联失效；
- 模型未安装、CLI 参数变化、JSON 不合法、用户取消和进程重启均返回真实失败状态。
- 同一投递读取和同一待确认写入分别从 GUI、机器 CLI、TUI 与斜杠 Skill 发起，得到一致结果、提案和审计记录。

## 阶段 1：邮箱与投递进度闭环

### 用户结果

OfferU 在托盘驻留期间增量读取授权邮箱，把求职消息转成可解释的候选进展；用户确认后，投递概览和阶段时间线同步更新。

### 实施范围

- Gmail 增量轮询与 IMAP 增量同步、断点和幂等键；
- 消息证据快照与完整正文显式保存；
- 确定性标识匹配与 Agent 候选排序；
- 待归属消息、候选进展、用户确认和投递阶段事件；
- 一行一次投递尝试、摘要表、可选阶段列和详情时间线；
- 邮箱优先，短信采用分享、粘贴或转发导入；
- 进展结果产生学习观察，但不直接改写职业事实。

### 发布门槛

**安全不变量**

- 未经使用者确认写入正式投递阶段事件的次数为 0；
- 同一 provider/message-id 重复同步产生的外部进展信号最多一个；
- 多个合理投递候选时自动建立正式关联的次数为 0；
- 默认保存完整邮件正文的次数为 0；
- 邮箱凭据进入数据库、日志或 Agent 上下文的次数为 0。

**概率与可靠性基准**

- 在不少于 300 条去标识化标注消息上，求职消息识别 macro-F1 不低于 0.95，阶段类型识别 macro-F1 不低于 0.92；
- 确定性匹配的错误关联率为 0；Agent 对歧义样本的候选 Top-3 recall 不低于 0.95；
- 重启、网络中断和重复轮询后，消息遗漏率与重复率均为 0。

**端到端与故障恢复**

- 连接邮箱 → 托盘增量同步 → 候选进展 → 用户确认 → 时间线与概览更新 → 学习观察；
- 同公司多岗位、同岗位复投、转发邮件、取消面试、改期和无对应投递消息均有固定场景；
- 撤销邮箱授权后立即停止同步并级联失效来源派生内容。

## 阶段 2：公司/岗位调研与证据化简历优化

### 用户结果

使用者给出 JD 后得到持续更新的公司档案、岗位档案和逐条引用的调研报告，并只使用已确认职业证据生成岗位化简历建议。

### 实施范围

- 官方来源与公共搜索自动研究；
- 登录态平台只通过用户主动发起的本机只读浏览器会话研究；
- 公司档案、岗位档案、证据快照、来源等级和版本；
- 面经信号与匿名简历表达模式；
- 本地深度执行器运行研究任务并返回候选结果；
- JD 匹配、事实门、简历差异和采纳/拒绝；
- 调研与简历行为产生学习观察。

### 发布门槛

**安全不变量**

- 硬事实结论带具体来源的比例为 100%；
- 主观信号满足双来源或明确标记“单一信号/未知”的比例为 100%；
- 绕过登录、验证码、robots、频率限制或执行外部副作用的次数为 0；
- 简历建议中未被职业证据支持的经历、技能和成果为 0；
- 保存或近似复刻真实候选人完整简历的数量为 0。

**概率与可靠性基准**

- 在不少于 100 份标注 JD 上，字段抽取 macro-F1 不低于 0.95；
- 研究输出 schema 合法率不低于 99%，失败不得降级为无引用报告；
- 同一来源重复发现后的有效证据重复率低于 1%；
- 引用链接、抓取时间、来源等级和原始快照哈希完整率为 100%。

**端到端与故障恢复**

- 导入 JD → 公司/岗位档案 → 公共与授权研究 → 调研报告 → 简历差异 → 用户采纳 → 学习观察；
- 冷门岗位、只有单一主观来源、登录态过期、网页删除和研究任务取消均能明确降级；
- 刷新调研不会静默覆盖旧证据，撤销来源会级联更新报告与建议。

## 阶段 3：轮次式语音与视觉 AI 面试

### 用户结果

使用者可以按岗位进行轮次式语音或文字面试，获得带证据的内容评价，以及包含姿态、手势和可观察面部模式的独立表达行为报告。

### 实施范围

- 逐题 TTS、录音、端点检测、STT 与文字兜底；
- 题目、回答、转写与岗位档案、职业证据关联；
- 本地姿态、明确手势和可观察面部模式事件；
- 声明式、版本化评分规则；
- 内容评价与表达行为反馈分离；
- 面试观察进入记忆巩固，但不自动成为职业事实；
- 默认不保存原始音频、视频、截图或逐帧 landmarks。

### 发布门槛

**安全不变量**

- 默认落盘或上传的原始音频、视频、截图和逐帧 landmarks 数量为 0；
- 每项内容评分包含 rubric 版本、证据引用和解释的比例为 100%；
- 表情、姿态、手势进入内容分或录用概率的次数为 0；
- JSON 或模型失败时返回固定假分的次数为 0；
- 人格、诚信、情绪、心理状态或岗位胜任力推断的次数为 0。

**概率与可靠性基准**

- 安静普通话标注集上的转写字符错误率不高于 15%，且始终提供文字修正与文字作答兜底；
- 本地端点检测从用户停止说话到结束本轮的 P95 不高于 1.5 秒；
- 在版本化标注视频集上，正式报告事件 precision 不低于 0.90、recall 不低于 0.85；
- 评分结构化输出合法率不低于 99%，其余请求必须明确失败而不是伪造分数；
- 同一输入、同一 rubric 和同一模型版本重复评价的维度分标准差必须记录并低于预设容差。

**端到端与故障恢复**

- 选择岗位与 rubric → 语音/文字回答 → 本地表达事件 → 内容评价与表达报告 → 学习观察；
- 麦克风或摄像头拒绝授权、设备中断、STT 失败、模型超时、用户重录和会话恢复均有文字兜底或真实失败状态；
- 报告中能查看每类表情/手势/姿态的次数、持续时间、置信度和证据时间段，但这些数据不进入内容评分。

## 不在第一阶段范围

- SaaS、多租户、组织、登录、计费与云端全天候同步；
- Android 短信伴侣或默认短信应用；
- 全双工可打断实时语音；
- 原始面试媒体云端保存；
- 任意 Python、JavaScript 或 shell 评分 Skill；
- 绕过平台技术措施的服务端爬虫；
- 自动投递、自动联系招聘方或自动改变外部账号状态。
