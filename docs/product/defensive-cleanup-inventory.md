# 防御性设计盘点：删什么 / 留什么（待确认）

> 目的：OfferU 是**本机单用户**应用，很多拦截是按「多方协作、不可信 Agent、要审计」的标准写的。结果就是：功能一碰就 stale/blocked，用户觉得「啥都用不了」。
> 这份清单只是**提案**。删之前，我会逐个模块核对调用关系，每删一批就把主线（粘贴 JD → 定制 → 采用 → 导出）真跑一遍。

## 1. 规模

| 类别 | 规模 |
| --- | --- |
| 「Proposal v2」审批计划机制（`proposal_plan_*`、`decision_plans`、确认组、回执、摘要、续跑） | 约 5,300 行 |
| 策略 / 守卫 / 注册表（`career_policy`、`main_agent_guardian`、`capability_plugins`、`agent_*_registry`、`agentic_interaction_policy`、`ui_approval_capability`、`reset_write_guard`、`application_action_registry`） | 约 3,700 行 |
| 上面这些机制对应的测试（27 个文件） | 约 8,100 行 |
| 后端测试总量 | 119 个文件、约 35,600 行 |
| 拦截最密集的业务模块 | `role_intelligence`、`resume_optimization`、`career_delivery`、`career_tasks`、`job_research`（每个都有 70–160 处拦截） |

## 2. 建议删除

| 对象 | 为什么删 | 用什么替代 |
| --- | --- | --- |
| Proposal v2 的「封存计划 + 确认组 + 执行回执 + 显示摘要校验」 | 单用户本机应用里，界面上点的就是用户本人；同一个确认要校验摘要、回执、能力令牌三遍 | 一张 `pending_actions` 表：Agent 提议 → 用户点「采用 / 跳过」→ 执行，失败就显示原因 |
| 「先做投前决策才能进简历工作区」这类**阶段门** | 强行规定操作顺序，用户想先改简历就改不了（#93 已删简历这一处） | 只用来提示下一步，不做拦截 |
| 「生成后有变化就 stale」 | 正常使用中，JD、档案会一直变；每改一次就作废之前的工作 | 提示「生成后有变化」（#93 已改简历这条路） |
| 整份提案级别的 blocked | 一条有问题，所有条都用不了 | 逐条检查（#93 已改） |
| 只为绕过上述拦截而写的 mock 测试 | 测的是拦截本身，不是功能 | 删除 |
| 打包和发布用的守卫测试（`release_*`、`rustsec_policy`、`macos_hdiutil_shim`、`branch_guard`） | 内测阶段不发正式版，每次跑一遍都白跑 | 挪到手动触发的发布检查里，不进日常测试 |

## 3. 建议保留（核心测试也只留这些）

| 对象 | 为什么留 |
| --- | --- |
| 事实闸门（`resume_fact_gates`）：数字、公司、学校、项目名、奖项、时间 | 这是产品承诺「不编造经历」的底线；改成**逐条**检查，不再拖累整份 |
| 粘贴 JD 识别（`job_capture`）：字段必须是原文子串 | 防止模型编出原文里没有的公司 |
| 匿名抓取的站点黑名单（BOSS、小红书等） | 合规底线，你明确要求过 |
| 用户手改的内容不被 AI 覆盖 | 用户信任的底线 |
| 导出（PDF / 数据导出） | 用户最终要的产物 |
| 不可逆操作（投递、发邮件、删除）前确认一次 | 本机也需要，但一次就够，不要摘要 + 回执 |

## 4. 需要你判断

1. **Agent 写操作的确认**：要不要整体改成「可撤销即可，不先审批」？只有发邮件、投递这类不可逆操作才先问一次。
2. **审计日志**（`OperationAuditLog`）：要不要保留成一张简单的事件流水（视频里的「时间线」正好用得上），去掉签名和回执？
3. `role_intelligence`（2,584 行）和 `career_delivery`（1,861 行）里大量拦截，是不是先跳过，等主线跑通再说？

## 6. 执行顺序（每步一个小 PR）

1. 测试瘦身：删掉第 2 节列的测试，日常只跑核心测试（目标是 1 分钟以内）
2. 用 `pending_actions` 替换 Proposal v2，Agent 采用 / 跳过走同一条路
3. 去掉其余阶段门和 stale 判定（投递、面试、档案）
4. 同步更新文档
5. 每一步都在本机真跑一遍主线；跑不通就不合并
