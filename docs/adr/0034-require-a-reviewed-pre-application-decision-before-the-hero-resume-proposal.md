# ADR-0034：英雄闭环先完成可复核投前决策

- Status: accepted
- Date: 2026-07-28

## Context

现有“求职自动流水线”实际由岗位抓取与分拣、异步岗位调研、简历提案三个分离流程组成。它没有持久化“这个岗位是否值得投”的业务结论，也没有把调研中断、证据不足、使用者覆盖 Agent 建议和正常不投表达为可恢复状态。把这些能力继续交给一轮自由 Agent 对话串联，会隐藏异步边界与失败位置，并允许简历生成成本先于使用者的投递意愿。

## Decision

OfferU 的首个 Agent 英雄闭环采用确定性投前决策工作流：

1. 以一个真实岗位、默认使用者职业模型中的已确认职业证据、该岗位最近一次已完成调研为输入；
2. 调研任务仍由本地深度执行器异步完成，主 Agent 只读取其事实门后的结果；
3. 主 Agent 只能提出投、有条件投、不投或证据不足，并逐条引用允许的输入来源；
4. 使用者最终选择与 Agent 建议分别、可审计地保存；覆盖建议时必须说明理由；
5. 只有使用者最终确认投或有条件投，闭环才提议生成可审核简历提案；
6. 不投、证据不足、调研进行中和失败均是显式状态，不创建投递尝试，也不提交外部申请；
7. 固定阶段由 OfferU 自身的持久化状态机编排，不引入 Pi、LangGraph 或其他 Agent 框架。LLM 只承担证据归纳和建议生成。

## Consequences

- GUI、CLI、TUI、斜杠 Skill 和主 Agent 通过同一 Operation Registry 读取和推进投前决策；
- 异步调研完成后可以从持久化状态继续，不需要保留一条长时间运行的模型会话；
- 简历提案之前多一个明确人工确认点，但避免为明确不投的岗位生成材料；
- 投前决策需要独立生命周期，不能退化为普通 Markdown 材料或聊天文本；
- 第一阶段仍保持本地单人边界，使用原子本地持久化，不新增 SaaS、登录或多租户模型。

## Rejected alternatives

- 让 Agent 达到分数阈值后自动继续：统一分数掩盖证据质量差异，也绕过使用者的最终投递意愿；
- 只展示匹配分：无法形成可恢复的业务状态，也不能定义何时允许继续生成材料；
- 用通用 CareerArtifact 保存结论：该材料接口没有待复核、已确认和使用者覆盖建议的生命周期；
- 直接引入 Agent 编排框架：当前路径固定且现有 Operation Registry 已提供确认与审计边界，新增框架只会复制状态和权限语义。
