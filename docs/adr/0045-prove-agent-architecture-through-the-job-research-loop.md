# 用岗位调研闭环验证两条 Agent 路线

两条 Agent 路线的第一条联合纵向切片嵌入投前决策闭环：使用者选择真实岗位后，主 Agent 通过 Skill Registry 规划调研，创建带任务能力授权的托管执行会话，委托本地深度执行器形成带来源的公司与岗位候选研究结果，再由 OfferU 的证据规则、事实门和使用者审核决定哪些内容进入公司档案、岗位档案和后续投前决策。该切片必须覆盖事件流、取消、应用重启后的恢复、审计和失败状态，且外部执行器不能直接写入领域事实。选择岗位调研而不是孤立 AgentCore 或 Provider 接入，是为了用一个用户可见闭环同时验证内置主 Agent 与外部执行器的边界。
