## 1. 切片目标（10 行内复述）

构建 OfferU 第一个端到端纵向切片：JD 落库 → 读取 Profile→ 简历优化 Skill + 事实门校验 → HITL 提案 → 确认后写 ResumeVersion → 创建 ApplicationAttempt → 写 OperationAuditLog。  
该切片一次贯通 Profile 分层写权限（ADR-0002）、一行一次投递尝试（ADR-0007）、统一 Operation Registry（ADR-0029）三条核心架构，是后续学习观察（ADR-0011）与记忆收件箱（ADR-0025）的前置依赖。  
验收映射：JD 入库可查 / generate_resume 返回 resume_id + fact_gates / HITL 确认后落 ResumeVersion / 投递尝试一行一条 / 每步均有 OperationAuditLog。

## 3. 数据流分析（含 HITL 暂停点）

```
[1] JD 导入
    输入：JD 文本（或扩展批次）
    → POST /api/jobs/ingest（批量）或 新 Operation import_jd
    → jobs 表 + Batch
    → OperationAuditLog(ok, surface=cli/ui)

[2] 读取 Profile + ProfileSection
    → get_profile + list_profile_evidence Operation
    → 返回扁平摘要 + 条目列表
    →（缺口：无分层标识，ADR-0002 尚未落地）

[3] 读取 Job
    → get_job Operation
    → 返回 raw_description

[4] 简历优化 Skill 运行
    → generate_resume Operation（dry-run 模式，因 side_effects 含 llm+write）
    → 内部：_select_sections_structured（LLM选段）
            _skills_pipeline_rewrite（skill pipeline 改写）
            _fact_gates_validate（事实门校验，警告挂载 _gate_warnings）
            _create_generated_resume（写入 Resume + ResumeSection）
    → 返回 {resume_id, fact_gates, missing_keywords, ...}
    → Proposal 暂存（_PROPOSALS[proposal_id]）
    →（缺口：未创建 ResumeVersion 快照）

[5] HITL 确认门 ← 关键暂停点
    → 用户审查 fact_gates.warnings + missing_keywords
    → 若有 unverified_metric/unverified_org 警告：用户必须显式 ack 才能继续
    → POST /api/agent/confirm {proposal_id}
    → execute_operation(dry_run=False) 真正提交
    →（缺口：confirm 仅重放 generate_resume，未挂钩 ResumeVersion commit）

[6] ResumeVersion 落盘（确认后）
    → create_version_snapshot(resume_id)
    → ResumeVersion 表写入（含 Resume+Section 快照）
    → OperationAuditLog
    →（缺口：confirm 流程未调用 create_version_snapshot）

[7] 创建 ApplicationAttempt
    → 新 create_application_attempt Operation
    → 写入 Application 表（或新 ApplicationAttempt 表，待 ADR-0007 确认承载位置）
    → 写 application_event(created)
    →（缺口：当前 create_application 写 ApplicationRecord，与 ADR 冲突）

[8] 写 AuditEvent / OperationAuditLog
    → 每步 execute_operation 自动写 OperationAuditLog
    → 投递事件写 application_events JSON
    →（缺口：双轨事件存储，本切片统一到 OperationAuditLog + application_events）
```

## 6. 风险与阻断项

### ✅ 已确认的阻断项决策（2026-07-17 用户拍板）

1. **ApplicationAttempt 承载位置**（ADR-0007 落地方式）  
   决策：**新建独立 `ApplicationAttempt` 表**。独立表最贴近 ADR-0007「一行一次投递尝试」语义，不污染 workspace 表。需新增 1 个模型 + `create_application_attempt` Operation。

2. **Profile 分层字段是否阻塞本切片**  
   决策：**本切片只加 `tier` 字段占位**（verified_fact/preference/career_hypothesis），canonicalize 支持 tier 输入；完整写权限守卫延后到下一切片。

3. **HITL 确认挂钩范围**  
   决策：**仅挂 `generate_resume`**。confirm 后只有 generate_resume 追加 `create_version_snapshot` 调用，其他 tool 走各自 Operation 不挂钩快照。

4. **ResumeVersion 快照创建挂载点**（落盘前核实代码后引发的阻断问题）  
   事实源：`execute_operation`（ops.py:1061）在 `dry_run=True` 时不调 `op.fn`，只返回 skipped envelope；Resume 实际只在 confirm 路径（dry_run=False）落盘。原计划 P0-03 在 `_generate_for_job` 内、P0-05 在 confirm hook 两处都创快照 → confirm 一次产生**两个** ResumeVersion，违反"一份快照"。  
   决策：**放 P0-05 confirm hook**。P0-03 改为 NO-OP。语义最贴「确认后才落快照」，HITL 挂钩显式可审计；非 HITL 路径（直接 execute dry_run=False）也会因 confirm hook 缺席而不会产生多余快照，由调用方走正式 confirm 流程保证唯一性。

### 已评估的非阻断风险
- 事件双轨（application_events JSON + OperationAuditLog）暂不合并，ADR 未要求。
- `_PROPOSALS` 内存存储、重启丢失，本切片不持久化（超出范围）。
- 语义搜索 fallback 已处理，本切片不依赖 Vector DB。
