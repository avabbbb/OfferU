# 文档/README 对抗评审 — 2026-09-19

## 结论（对照 Apple 上线水准一句话定性）

README 本身已经是「合格的工程师 README」——结构干净、宣称大多数能在代码里找到对应物、资产全部落盘；但离 Apple 级产品页仍有明显距离：**首屏缺真正 hero 叙事、产品入口名与 UI 实际标签漂移（README 叫 Job，Sidebar 叫 Opportunity）、19 份顶层 markdown 没有清晰读者分流、Release Gate 叙事把普通用户挡在门外**。最大问题不是事实错误，而是「写给谁看」这件事没有回答清楚。

## Top-5 修复优先级

1. **D1 命名对齐** — README `Job` ↔ Sidebar `Opportunity` ↔ GOAL `Job / Opportunity` 三方漂移，是用户第一次打开产品就会撞到的「找不到入口」级矛盾；一次 sed + 决策即可修复。
2. **D4 顶层文档分流** — 19 份平铺 md 没有读者地图；在 README 尾部加 5 行 Documentation map 就能解决 80% 的迷路问题，成本极低收益极高。
3. **D2 Connect→Auto→Ready 文案-UI 对齐** — README 把它当产品支柱宣传，UI 里一个字都找不到；要么改 UI 步骤名，要么 README 改说人话，否则「产品方向」这句话是空宣称。
4. **D9 首屏重构** — Apple 标准的 hero：一句话主张 + 静态可控 hero 图 + badge；现在 logo→tagline→6.4MB GIF→Beta 声明的信息层级，首帧不可控且把最强的「持续理解/自动维护」卖点埋在副标题。
5. **D5 截图资产真实性** — 8 张 `.png` 实为 WebP 改后缀，且一半截图（email/calendar/settings/jobs-list）未被引用；改真 PNG 或改后缀 + 补齐 surface 叙事，10 分钟工作量消除一个 craftsmanship 黑点。
