CAREER OS · PRODUCT BLUEPRINT

Agent 可以换。
职业状态不能丢。

OfferU 不是另一个求职聊天框，而是一套由 Skill 生态驱动、由 Desktop 承载长期职业状态的 Career Operations System。

把“求职”从聊天，变成持续运转的系统。

06 · Human in the Loop

不要审批 79 个命令。
只在人真正该决定的地方停下来。

把 Ask 与 Approval 分开：Ask 是协作，Approval 是授权。底层写操作可以审计，但不等于都需要用户点击。

Ask

“你想怎么做？”

✓ 产品型还是技术型定位
✓ 是否突出开源
✓ 哪几个岗位今天优先投
✓ 是否授权读取工作目录
≠

Approval

“我要执行高风险 / 不可逆动作。”

✓ 新 Career Truth
✓ 外部发送 / 最终提交
✓ 敏感字段 / 账号注册
✓ 删除重要用户数据

07 · Connectors & Lazy Setup

能力按需出现。
不要第一天把用户配到崩溃。

Onboarding 只完成 Desktop + Profile + Goals。BOSS、邮箱、Playwright、ATS 登录都在第一次真正需要时才配置。

JUST-IN-TIME

BOSS Connector

定位：Job + Progress，不是 Profile importer。

  • Search / Detail / Recommendation
  • Applied / Interviews / Chat state
  • Greet / re-engagement candidates
  • 映射回同一 Job / Application
JUST-IN-TIME

Browser Automation

只有用户点击投递辅助时才检测。

  • 注册 / 登录 / 填表 / 上传
  • 复用已授权登录态
  • OTP / CAPTCHA / 2FA 用户接管
  • Receipt capture
JUST-IN-TIME

Email / Calendar

作为进展 Evidence Source，而不是直接改 Pipeline。

  • 分类 / 关联 / 去重
  • Ambiguity review
  • Interview signal
  • Progress candidate → stage event

09 · Long-lived Product

用户几天不打开，系统也不能失忆。

测试需要“全清”；长期用户需要“蒸馏继续”。两条路径不能混在一起。

Clean Reset · Owner Dogfood

1. Backup

备份 OfferU 数据，不动外部真实简历与 Agent Memory。

2. Clear

清 Career data / onboarding / session / cache。

3. Fresh Start

模拟真正第一次安装用户。

Distill & Continue · Real User

旧对话 / 旧 Task / 旧 Cache

检测 stale / duplicate / transient。

→ Historical Node

“投递腾讯 Agent Runtime；简历改为产品/FDE 双定位；英语口语为主要缺口。”

→ Refresh

保留事实、决策、证据与结果；刷新外部现实信息。
