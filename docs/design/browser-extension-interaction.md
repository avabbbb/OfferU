# OfferU 浏览器扩展交互设计

> 状态：approved interaction spec，尚未实施  
> 日期：2026-08-10  
> 架构源：[浏览器扩展框架契约](../architecture/browser-extension-framework.md)  
> 安全边界：[ADR-0049](../adr/0049-unify-browser-job-collection-and-application-form-fill.md)

## 1. 交互结论

主界面采用浏览器原生侧边栏，不用 popup 承载填表长流程，也不往招聘页面注入一整套悬浮产品 UI。工具栏点击完成三件事：授予当前 tab 的临时权限、打开 OfferU 侧边栏、扫描当前页。

侧边栏根据当前页面自动给出一个主动作：

- 岗位列表/详情页：采集岗位；
- 已验证 ATS 表单：扫描表单；
- 当前填写会话后的成功页：检查提交结果；
- 未适配或冲突页面：只生成脱敏适配报告。

用户不需要先判断“这是哪个插件功能”，也不会同时看到“采集、填表、投递”三个容易混淆的大按钮。

## 2. 信息架构

```text
┌────────────────────────────────┐
│ OfferU                 ● 已连接 │
│ 当前站点：Moka · 表单规则 v1.2 │
├────────────────────────────────┤
│ 当前页                         │
│ 岗位篮 (3)                     │
│ 活动记录                       │
├────────────────────────────────┤
│ [随页面类型变化的主工作区]     │
├────────────────────────────────┤
│ 隐私与权限说明          设置 ⚙ │
└────────────────────────────────┘
```

- `当前页`：唯一主工作流，自动识别页面类型；
- `岗位篮`：本地待同步候选与逐条同步结果；
- `活动记录`：最近扫描、填写和候选确认的脱敏审计，不显示完整字段值；
- `设置`：OfferU 连接地址、诊断模式和清除本地数据。

## 3. 全局状态

| 状态 | 主文案 | 主动作 | 禁止行为 |
|---|---|---|---|
| OfferU 离线 | 无法连接本机 OfferU | 重新连接 | 假装同步成功 |
| 浏览器受限页 | 浏览器不允许扩展读取此页面 | 无 | 反复请求权限 |
| 正在识别 | 正在识别当前页面… | 取消 | 提前显示填写 |
| 已验证岗位页 | 可采集当前岗位 | 预览岗位 | 直接写入 OfferU |
| 已验证表单 | 可安全扫描此表单 | 扫描表单（不会填写） | 扫描时写 DOM |
| 实验规则 | 此页面仅支持诊断 | 生成脱敏适配报告 | 填表 |
| 规则冲突 | 无法可靠判断页面类型 | 生成脱敏适配报告 | 猜一个 Adapter |
| 当前会话成功页 | 发现可能的提交回执 | 检查提交结果 | 自动记为已投递 |

Header 始终显示连接状态、站点/ATS 名称、规则版本和支持级别。`verified` 显示“已验证”，`experimental` 显示“仅诊断”；不要只用绿色/黄色区分。

## 4. 岗位采集流程

### 4.1 预览

```text
┌ 当前岗位 ──────────────────────┐
│ 后端工程师                     │
│ 示例公司 · 深圳                │
│ 来源：当前详情页               │
│                                │
│ 已读取                         │
│ ✓ 职位名称  ✓ 公司  ✓ JD       │
│ ✓ 地点      ? 发布日期         │
│                                │
│ [加入岗位篮]                   │
└────────────────────────────────┘
```

规则：

- 第一次扫描只生成预览；
- 缺失字段显示“未识别”，不猜测；
- 来源 URL 始终可见；
- “加入岗位篮”只写本地队列，不代表已投递。

### 4.2 同步

岗位篮每条记录显示 `待同步 / 同步中 / 已同步 / 失败`。批量按钮使用精确文案：`确认同步 3 个岗位到 OfferU`。确认面板列出新增、可能重复、信息不全三组；后端逐条确认成功前不能删除本地条目。

成功文案使用“已加入 OfferU 岗位库”，禁止使用“已申请”“已投递”。

## 5. 表单填写流程

### 5.1 前置门

开始前必须同时显示：

- 当前关联岗位；
- OfferU 连接状态；
- 投前决策是否允许继续；
- 当前规则包是否 `verified`；
- 本次只会填写非敏感空白字段。

任一门不满足时，主动作变为解决问题，例如“选择 OfferU 岗位”“返回 OfferU 完成投前判断”或“导出适配报告”，不能提供绕过按钮。

### 5.2 只读扫描

主按钮固定写：`扫描表单（不会填写）`。扫描期间侧边栏显示阶段，但不得自动展开区块、添加经历、打开下拉、聚焦输入框或改变页面。

```text
识别当前表单
✓ 站点规则       Moka v1.2
✓ 扫描字段       24
✓ 匹配职业事实   11
✓ 安全检查       完成
```

### 5.3 填写预览

结果分四组，不把所有字段混成一个 checklist：

1. `可填写`：空白、非敏感、规则已验证、事实已确认；
2. `受保护`：已有值、敏感、承诺/同意、文件、低置信；
3. `需要你处理`：开放题、附件、复杂未支持控件或缺少事实；
4. `未识别`：页面字段无法稳定定位或匹配。

```text
┌ 可填写 7 ──────────────────────┐
│ ☑ 姓名      张＊  来源：基本信息│
│ ☑ 邮箱      a＊＊@mail.com      │
│ ☑ 手机      138＊＊＊＊1234      │
│ ☑ 学校      示例大学           │
└────────────────────────────────┘
┌ 受保护 5 ──────────────────────┐
│ 🔒 身份证号   敏感字段           │
│ 🔒 期望薪资   承诺性字段         │
│ 🔒 工作许可   需要本人判断       │
│ 🔒 简历附件   不自动上传         │
│ 🔒 隐私同意   不代替你同意       │
└────────────────────────────────┘

        [确认填写 7 个空白字段]
```

预览值默认脱敏；点击单行可以在一次会话内查看来源，但侧边栏不持久化完整值。使用者可以取消某个可填写项，不能把受保护项强行改成自动填写。

### 5.4 二次确认

确认层必须明确：

```text
将填写 7 个空白字段

不会覆盖已有内容，不会上传附件，
不会勾选同意项，也不会提交申请。

[取消] [确认填写]
```

不要使用“智能投递”“一键申请”“全部自动完成”。

### 5.5 执行与结果

逐字段显示 `等待 / 已填写并验证 / 页面拒绝 / 页面已变化 / 已跳过`。部分失败就是部分结果，不能显示全局绿色成功。

```text
本次结果
✓ 已填写并验证  6
! 页面拒绝      1
○ 需要你处理    10

请检查整份申请，再由你亲自点击网站的提交按钮。

[在页面中定位失败项]
[撤销本次仍未被修改的填写]
```

“撤销”只清除带本次 session marker 且写入后没有被用户/页面再次修改的字段；无法证明时不清除，并显示原因。

## 6. 使用者亲自提交后的候选确认

扩展不监听或代理最终提交按钮。使用者提交后，可以点击侧边栏的 `我已自行提交，检查结果`；如果同源页面导航仍处于 activeTab 临时权限内，Background 也可以提示重新检查。跨域后必须要求使用者再次点击扩展授权。

```text
┌ 发现可能的提交回执 ────────────┐
│ 示例公司 · 后端工程师           │
│ 发生时间：14:32                 │
│ 申请编号：＊＊4821              │
│ 证据：成功标题 + 当前岗位一致    │
│                                │
│ 这一步只会记入 OfferU，          │
│ 不会再次向网站提交。             │
│                                │
│ [不是这次] [确认已提交并记入]    │
└────────────────────────────────┘
```

候选生成后数据库仍无新正式投递尝试。只有点击 `确认已提交并记入`，Operation Registry 才原子创建 `ApplicationAttempt + Submitted event`。

## 7. 未适配页面与规则反馈

未适配页面不能用通用 Adapter 猜着填。侧边栏提供 `生成脱敏适配报告`，默认只包含：

- 页面 origin 的脱敏形式、page kind 猜测和时间；
- 候选规则 ID、版本、得分、正/反信号名；
- tag、role、input type、label/placeholder 的脱敏结构摘要；
- 控件框架线索、字段数量、未支持控件类型；
- 浏览器/扩展版本和错误码。

默认不包含字段值、完整 URL query、Cookie、localStorage、HTML、截图或简历内容。需要 fixture 时必须由使用者在诊断模式单独确认，保存前再次展示脱敏预览。

反馈界面给出可直接发给实现 Agent 的路径，不自动上传到任何服务。

## 8. 错误设计

每个错误包含“发生了什么、有没有写入、用户下一步”：

- `OfferU 未运行`：没有同步或填写；提示启动后端并重试；
- `页面在扫描后变化`：没有执行计划；提示重新扫描；
- `规则冲突`：没有填写；提示导出报告；
- `部分字段失败`：列出成功与失败，不重跑成功字段；
- `权限已失效`：没有继续读取；提示重新点击扩展；
- `候选确认失败`：网站不会被再次提交，pending candidate 保留。

禁止只显示“出错了”“操作失败”或返回伪成功。

## 9. 可访问性与视觉约束

- 侧边栏目标宽度 360–420px，在 320px 仍不横向滚动；
- 所有状态同时使用图标、文字和结构，不只依赖颜色；
- 主按钮每屏最多一个，危险/确认动作不与普通链接同样式；
- 键盘可遍历、焦点可见、错误与字段行建立可读关联；
- 动画遵守 `prefers-reduced-motion`；
- 不在招聘页面上覆盖提交按钮或拦截用户输入；
- 页面高亮是短暂辅助，关闭侧边栏或切 tab 后清理。

## 10. 文案黑名单

不得出现：

- 自动投递、一键投递、无人值守申请；
- 填写完成 = 已投递；
- 100% 支持某招聘网站；
- AI 已确认你的身份/资格/薪资；
- 安全无风险、绝不会出错。

允许的精确表述：

- `支持用户触发的岗位采集`；
- `先预览、再确认的非敏感字段填写`；
- `最终提交由你亲自完成`；
- `提交后生成候选，确认后记入 OfferU`；
- `此规则版本已通过指定 fixture 与浏览器验收`。

## 11. 交互验收

一个实现切片只有同时满足以下证据才可宣称完成：

1. WXT side panel 真实打开且无缺失资源/console error；
2. 工具栏点击后才获得当前 tab 权限；
3. 每个页面状态只有一个明确主动作；
4. 扫描阶段 DOM 零变化；
5. 预览能区分可填写、受保护、需处理、未识别；
6. 二次确认文案明确“不提交”；
7. 部分失败不显示全局成功；
8. 未适配页面只有诊断，不允许填写；
9. 提交候选确认前不创建正式投递事实；
10. 键盘、窄宽度、离线和权限失效状态可操作。
