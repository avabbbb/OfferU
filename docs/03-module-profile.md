# 03 · 模块：职业档案与记忆

> 状态：**当前设计权威** · 取代 career-memory-contract、owner-career-journey §2、proactive-career-director §9 等
> 用户入口：一级导航「档案」 · 主要代码：`backend/app/services/profile_*`、`career_memory.py`、`career_learning.py`、`memory_*`；`frontend/src/app/profile/`

## 1. 目的

让 OfferU 越用越了解用户，同时**绝不**把模型生成的总结变成用户无法审核的「事实」。

## 2. 用户看到什么

档案页首屏必须直接呈现：

| 区块 | 内容 |
| --- | --- |
| 已确认 | 身份、教育、工作 / 实习、项目、技能（含使用场景）、成果及证明、偏好 |
| 待确认 | 来自简历解析、对话、邮件、面试复盘、已授权 Agent 记忆的候选，每条附来源 |
| 缺口 | 针对当前目标岗位：强 / 弱 / 缺失 / 未知 / 表达不足 |
| 本次新增 | 最近一次建档或同步实际写入了什么、哪些还没确认 |
| 下一步 | 一个最有价值的补充问题或动作 |

**不使用通用的完整度百分比。** 完整度是「相对目标」的，校招和社招分别判断（Strategy Pack：`campus_search` / `experienced_search`）。

## 3. 记忆分五层，不能混为一谈

| 层 | 是什么 | 存放位置 | 是否每次注入 Agent 上下文 |
| --- | --- | --- | --- |
| **Career Truth** | 结构化、用户可编辑的事实与流程状态 | 本地 SQLite + 文件 | 只注入相关部分 |
| **精选职业记忆** | 小而新、用户可见可改：稳定偏好、反复出现的纠正、已接受的职业假设、复盘得出的经验 | OfferU 记忆记录 | 精简版 |
| **情景学习** | 面试复盘、LearningObservation、被拒或暂缓的 MemoryProposal、日报和周报 | 情景记录 | 否，按需检索 |
| **前瞻记忆** | 将来要发生的事：N 天后跟进、明天面试、待做决定 | Calendar / CareerTask / Automation / Proposal（结构化，带到期时间） | 只注入当前相关项 |
| **外部 Agent 记忆** | Codex、Claude Code、WorkBuddy 等宿主自己的记忆 | 宿主自己 | 否，属于可选来源 |

规则：

- 将来要做的事**必须**存成结构化状态，不能只写在记忆文字里、指望模型记得。
- 读取外部 Agent 记忆前必须获得用户明确授权，并且只导入相关片段；导入的内容只能成为候选。
- 「问过三次」不等于「三次都答得弱」；「观察到一次」不等于「反复出现」。

## 4. 写入路径（唯一）

```text
来源：简历 / 用户陈述 / 面试 / 邮件 / 已授权的 Agent 记忆
  → Observation 或 Candidate
  → 来源记录 + 校验 + 去重或替代
  → MemoryProposal / 证据门
  → 需要时由用户或策略审核
  → 精选记忆和 / 或已确认的档案
```

模型不能因为某个推断在聊天里反复出现，就把它升级为已确认的 Career Truth。涉及雇佣经历、成果、数字、作者身份的内容，必须先有 OfferU 内的证据并经过审核。

## 5. 读取路径

1. 解析出当前相关的 Skill；
2. 只读取该 Skill 暴露的、最小必要的档案 / 证据 / 岗位 / 投递 / 面试 / 记忆上下文；
3. 基于这些有依据的上下文推理；
4. 准备安全的工作；
5. 持久改动走 Operation Registry → Proposal。

不要把所有记忆倒进每个 prompt，不要直接读 SQLite，不要把宿主记忆当作权威，不要在宿主里另建一份职业事实。

## 6. 渐进建档

| 时机 | 体验 | 验收 |
| --- | --- | --- |
| 有简历 | 用户指定目录或文件 → 展示文件及用途 → 读取选中的内容 | 不扫描整个磁盘；原文件保留 |
| 没有简历 | 一问一答的访谈 | 不把空白默认档案说成「已建档」 |
| 有 Agent 记忆 | 明确选择来源、范围和用途，先预览片段 | 不自动读取全部会话或凭据 |
| 后续使用 | 只在能推动当前决定时，问一个小问题 | 回答存为有来源的候选 |

访谈要围绕具体任务追问：「你做了什么、你负责哪一部分、结果是什么、证据在哪里」，而不是让用户给自己的能力打分。不知道的数字就保留为未知，不要逼出一个估算值冒充事实。

## 7. 职业阶段判断

根据毕业时间、全职经验、当前就业状态、目标 seniority 推断校招或社招，并允许用户纠正。不得根据年龄等敏感或无关属性推断。

- 校招侧关注：探索方向、招聘窗口、漏斗转化、从有限经历里挖掘潜力。
- 社招侧关注：市场定位、ownership 与影响力、流程节奏、重新联系旧岗位、薪酬 / 职级 / 谈判。

## 8. 刷新、整理与重置（四种不同动作）

| 动作 | 用户体验 | 必须保留 |
| --- | --- | --- |
| 更新程序 | 安装新版本 | 全部数据 |
| 刷新来源 | 显示上次刷新时间、本次新增 / 变化 / 失效的项、失败的来源 | — |
| **蒸馏为历史节点** | Agent 把选定的过时上下文整理成短摘要，预览后用户接受，再归档 | 已确认事实、投递结果、证据链接、修订历史、恢复和展开路径 |
| **全清重新开始** | 展示将清理的范围，先完成可恢复的备份，再单独确认（属于 `AUTHORIZE`） | 账号和 Key、安全记录、备份、审计；不删除原简历和外部 Agent 记忆 |
