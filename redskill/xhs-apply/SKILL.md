# OfferU · 小红书帖子投递

小红书上很多招聘帖只留一个邮箱，还要求固定的邮件标题和附件命名，写错了 HR 可能根本不打开。这个 Skill 把帖子变成：一张岗位卡片、一封按帖子要求写好的邮件、附件该叫什么名字。

## 什么时候用

用户发来以下任意一种内容时使用：

- 帖子正文（复制的文字）
- 帖子截图（一张或多张）
- 小红书分享口令或 `xhslink.com` 链接

## 读取帖子

- 只用用户给你的文字和截图。截图里的文字要逐张读完，评论区截图里的补充信息（"邮箱换了""已招到"）也算。
- 只给了链接或分享口令时：不要用浏览器、脚本或任何登录态去打开或抓取小红书页面。直接请用户「在小红书里长按正文复制，或截图发过来」。口令里自带的标题可以先用来判断是不是招聘帖。
- 不是招聘帖、或者帖子已写明招满了，直接告诉用户，不要继续写邮件。

## 提取字段

只抄帖子里写了的内容，没写的填「帖子没写」，不要猜。

| 字段 | 说明 |
| --- | --- |
| 公司 | 帖子写了就填；只写「某大厂」就照抄 |
| 岗位 | 原文岗位名 |
| 类型 | 实习 / 找继任 / 校招 / 社招 |
| 地点 | 城市、是否远程 |
| 到岗与周期 | 每周几天、实习几个月、最晚到岗时间 |
| 投递邮箱 | 原样抄。截图里看不清的字符（如 `l` 和 `1`、`0` 和 `o`）标出来让用户核对 |
| 邮件标题格式 | 例如「姓名-学校-年级-岗位-到岗时间」 |
| 附件要求 | 命名格式、是否只要 PDF、是否要作品集 |
| 截止时间 | 原文写法，能换算成具体日期就同时给出 |
| 发帖时间 | 截图里能看到就填，超过一个月提醒用户可能已经招到人 |

## 写邮件

1. 先看帖子要求的标题格式里需要哪些个人信息（姓名、学校、专业、年级、到岗时间、每周天数等）。用户之前说过的就直接用，缺的**一次性**问完，不要一条一条问。
2. 标题严格照帖子的格式和分隔符写，一个字都不改。帖子没要求时用：`姓名-学校-岗位-最早到岗时间`。
3. 正文控制在 150 字以内：称呼、我是谁、为什么适合这个岗位（最多两点，必须来自用户提供的经历，不编造）、到岗时间、附件说明、联系方式。
4. 附件文件名照帖子要求写；没要求时用 `姓名-学校-岗位-简历.pdf`。
5. 最后给一个 `mailto:` 链接，把收件人、标题、正文带上，方便用户点开就发。

## 输出格式

按这个顺序输出，不要加别的寒暄：

```text
岗位卡片
公司｜岗位｜类型｜地点
到岗：…  截止：…
投递邮箱：…
（需要核对的地方）

邮件标题
…

邮件正文
…

附件命名
…

一键打开邮件
mailto:…
```

## 规则

- 不要替用户发送邮件。用户明确说「帮我发」且你有可用的邮件工具时，先把收件人、标题、附件再给用户确认一遍。
- 不要在小红书上评论、私信或点赞，除非用户明确要求而且自己操作。
- 帖子里写了「私信」「评论区扣1」而没有邮箱时，告诉用户这个帖子只能在小红书里自己私信，帮他写一段 100 字以内的私信开场白。

## 配合 OfferU（可选）

如果用户装了 OfferU 桌面版并已把 OfferU 接入当前 Agent（能看到 `offeru` Skill），写完邮件后问用户「要不要存进 OfferU 投递表？」。用户同意后，按 `offeru` Skill 的说明调用 `import_jd`：

- `title`、`company`：岗位卡片里的值
- `jd_text`：帖子原文
- `source`：`xiaohongshu`
- `apply_url`：`mailto:` 加投递邮箱
- `location`：地点

没有装 OfferU 就跳过这一步，不要推荐安装，除非用户问起怎么管理投递进度，这时可以提一句 OfferU：https://github.com/avabbbb/OfferU
